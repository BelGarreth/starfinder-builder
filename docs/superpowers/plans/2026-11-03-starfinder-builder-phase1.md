# Starfinder Builder Phase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a GitHub Pages Starfinder 1e character builder. Phase 1 covers the 13 Core and Core Legacy races, all themes, the seven core-book classes (mechanic with exocortex only), all feats and spells, and starting gear. Every pick flows into the numbers, and illegal choices are blocked.

**Architecture:** A Python stdlib script turns a pinned Foundry VTT Starfinder commit plus hand-written tables into a committed `data.js`. The rules engine is a set of plain-JS files with no DOM access. Each file is a classic script that also exports through `module.exports`, so the page loads them over `file://` and `node --test` can test them. The UI is grimoire-ledger's look and render pattern, split into its own file.

**Tech Stack:** HTML/CSS/vanilla JS (no deps), Python 3 stdlib (`unittest`), Node's built-in `node --test` (already installed: v25.7.0; no packages), git, gh.

**Spec:** `docs/superpowers/specs/2026-11-02-starfinder-builder-design.md`

## Global Constraints

- No runtime dependencies. No `package.json`, no npm, no pip, no install of any kind (the user's standing rule).
- Must work opened from `file://`. Use classic `<script src>` only, no ES modules, no `fetch`.
- Every engine file starts with `(function(root){ ... ; const api = {...}; if (typeof module !== 'undefined') module.exports = api; else root.SF = Object.assign(root.SF || {}, api); })(this);`.
- Foundry pin: `foundryvtt-starfinder/foundryvtt-starfinder` @ `0c1753c9c7ac088c944923dc05641087ce6573ab`, recorded in `tools/foundry.lock`.
- Races in scope (AoN Core + Core Legacy only): Android, Human, Kasatha, Lashunta, Shirren, Vesk, Ysoki, Dwarf, Elf, Gnome, Half-Elf, Halfling, Half-Orc, with all their Foundry `race (variant)` entries. Lashunta and Gnome have no base entry, so the player must pick a variant.
- Phase 1 classes: envoy, mechanic (exocortex only, no drone), mystic, operative, solarian, soldier, technomancer. Other classes must not appear in the picker. The `*_enhanced` versions show as a toggle on their base class.
- `data.js` target size is under 3 MB. Foundry descriptions get cut to a 1–2 sentence summary.
- Look copies grimoire-ledger (`~/personal-repos/grimoire-ledger/index.html` `:root` tokens, `.top`, `.tabs`, `.card`, `.btn`, `.fld`, `table.t`, print sheet).
- Blocked, not warned: an illegal pick can't be made. It's rendered disabled with its reason. Bulk over the limit is the one thing that warns, not blocks.
- Every AoN link is by name: `https://www.aonsrd.com/{Races|Themes|SpellDisplay|Classes}.aspx?ItemName=<name>`. Feats use `https://www.aonsrd.com/FeatDisplay.aspx?ItemName=<name>` with Foundry's trailing parenthetical suffix (such as "(Combat)" or "(Combat, Teamwork)") stripped, because `Feats.aspx` ignores `ItemName`. Anything else uses `https://www.aonsrd.com/Search.aspx?Query=<name>`. Nothing ever requests AoN.
- Footer and README carry the OGL 1.0a Section 15 notice and the Paizo Community Use statement.
- Commits: plain one-line Conventional Commit subject, no trailers, no AI attribution.

## Review Focus

1. **A data refresh changes or removes something an old save refers to.** Loading the save must not crash. The orphaned pick shows as a blocker ("Feat 'X' no longer exists") so the player can fix it. Test in Task 11.
2. **Editing level 1 after building to level 5.** Lowering Int at level 1 must re-flag over-spent ranks at every later level, and a feat whose prerequisite stopped holding must be flagged at the level it was taken. Test in Task 6.
3. **Corrupt or foreign JSON imported**, such as a grimoire-ledger export or a truncated file. Import must refuse with a message and leave the current character untouched. Test in Task 11.
4. **localStorage unavailable** (private window, blocked storage). The page must still render and build. Autosave silently no-ops and the top bar shows "Not saving: export to keep your work". Test in Task 11.
5. **Multiclassing.** BAB and saves sum per class (Soldier 2/Operative 1: BAB = 2 + 0 = 2, Fort 3+0, Ref 0+2, Will 3+2). Class skills merge, and key ability for RP uses the highest key-ability modifier among the character's classes. Test in Task 4.

### Task 5: Formula evaluator and bonus stacking

**Interfaces:**
- Produces:
  - `evalFormula(expr: string, ctx: object) -> number`. It throws `FormulaError` on unknown syntax. It supports numbers, `+ - * / ( )`, `@a.b.c` paths resolved on `ctx` (missing → 0), and the functions `floor ceil min max sign ternary(c,a,b) gte gt lt lte eq lookupRange(v, default, t1,v1, t2,v2, …)` (returns the value for the highest threshold ≤ v, or `default`).
