# Starfinder Builder

A static Starfinder 1e character builder. No server, no dependencies: open `index.html` in any modern
browser. Phase 1 covers the Core and Core Legacy races, themes, and the envoy, mechanic, mystic,
operative, solarian, soldier and technomancer classes, with illegal picks blocked and explained.

Live at https://belgarreth.github.io/starfinder-builder/

## Persistence

State autosaves to the browser's `localStorage`. It survives reloads but stays in that one
browser on that one device, so export a backup if you care about it. If storage is blocked the page
still works and says so in the top bar.

## Run your own copy

1. Fork this repo.
2. **Settings → Pages → Deploy from a branch → `main` / `/ (root)`**.
3. A minute later it's live at `https://<your-username>.github.io/starfinder-builder/`.

## Regenerating data

`data/core.js`, `data/spells.js` and `data/items.js` are generated by `python3 tools/build_data.py` from
the Foundry VTT Starfinder system data pinned in `tools/foundry.lock`. It needs only Python 3 and no
packages. The page loads the three files as classic scripts and they merge into `SFDATA`;
`data/index.js` is the Node-only merged view used by tests. Each file stays under 3,000,000 bytes.

### Overrides

`tools/prereq_overrides.json` holds `{slug: {_why, prereq}}` for feats whose prerequisite text the parser
cannot read; a `text` check is shown but not enforced. `tools/effect_overrides.json` holds
`{slug: {_why, effects}}` where `effects` is `"none"` or a list of modifiers. They land in
`SFDATA.overrides.effects` and are not merged into a record's own `modifiers`. Situational bonuses use
`modifierType: "formula"` with a `condition`; only unconditional bonuses are `constant`. An entry may instead be `{_why, replace: true, modifiers: [...]}`: the build drops the record's own Foundry
modifiers, writes these in their place and sets `modifiersReplaced`, and the entry does not appear in
`overrides.effects`, so nothing is counted twice. The engine reads each record's `modifiers` plus
`overrides.effects[slug]`, as before. A constant may
carry `"when": "armor"`, meaning it applies only while armor is equipped, or `"when": "lightOrNoArmor"`, meaning only in light armor or none and not encumbered. The build fails if a feat has
no prerequisite or a bonus-bearing feat or feature has no constant modifier and no override.

### Class progressions

`tools/class_progressions.json` holds each Phase 1 class as `{levels: {"1".."20": [Entry]}, enhanced?: {levels}}`,
authored from the Core Rulebook class tables. It lands in `SFDATA.progressions[class]`. The build fails
if a class lacks any level from 1 to 20, or if an entry names a feature, feat, skill or choice id that
does not exist. An `_enhanced` class uses its base levels plus `enhanced.levels`. An enhanced choice
with the same id as a base choice at that level replaces it. An entry is one of:

- `{fixed: slug}`: the feature is gained at that class level.
- `{choice: id, label, pool, count, minLevelFrom?, allowKnown?, distinct?}`: the player picks `count` features,
  stored as `char.levels[i].choices[id]` (a slug or a list of slugs). In the source file `pool` may be
  `{category, exclude?, enhanced?}`, which the build expands to every feature of that class and category.
  In `SFDATA` it is a slug list or `{poolOf: id}`, meaning the same pool as choice `id`. A pick is
  blocked if it is outside the pool, if its `minLevel` is above the class level, or if it repeats an
  earlier pick or granted feature, unless the feature is `repeatable` or the entry has `allowKnown`.
  `distinct: field` makes the picks at one level differ in that field. Zenith revelations use
  `stellarType`, so each of levels 9 and 17 takes one graviton and one photon. A source pool may also
  give `excludeNeeds: [slug]`, which drops every option that needs one of those slugs.
- `{fixedOf: id, tier}`: grants the features the option chosen for choice `id` lists under
  `grants[tier]`. Fighting styles, connections and specializations get `grants` from their own text:
  the style techniques at 1/5/9/13/17, the connection powers at 1/3/6/9/12/15/18, and the specialization
  exploit (5) and power (11). The secondary fighting style uses tiers 1/5/9 at soldier levels 9/13/17.
- `{bonusFeat: true, pool?}`: an extra feat slot at that level; `pool` is `"combat"` or a feat slug list.
  Feat slots are matched by position: at each level the open slots sort first and restricted slots
  after them, and `char.levels[i].feats[j]` fills slot `j` in that order.
- `{skillPick: id, label, count, from?, minRanks?, classSkill?, skillFocus?}`: skills picked into
  `choices[id]`. `classSkill` makes them class skills and `skillFocus` gives the +3 insight bonus.
- `{abilityPick: id}`: one ability score key.

The build reads each pool option's "You must have … to choose/learn/select/take this" sentence. Named
features become `needs: [slug | [slug, …]]`, where a nested list means any one of them. A required
level raises `minLevel`, and "X as a class skill" becomes `needsClassSkill`. A pick is blocked until
every need is held at that point: by race, theme, class features or earlier picks. A requirement the
build cannot resolve to a record becomes `needsText`, such as a solar shield, a fly speed, four arms or
a known spell. That text is shown with the option but not enforced. A specialization's `skillFocus` list gives its associated skills the Skill Focus bonus. `_minLevels`
corrects a feature's level where Foundry's requirement text is wrong, such as the 11th-level exocortex mods.

Spells (mystic and technomancer): `char.levels[i].spells = {learn: [slug], swap?: {from, to}}` belongs to that
level's class, so multiclass casters keep one known pool per class. `spellSlots(char, data)` returns
`{[cls]: {known, perDay}}`; `perDay` adds `bonusSpellsPerDay` for the spell ability modifier and leaves out 0-level
spells, which are unlimited. A pick must be on the class list, castable at that class level, within the spell ability
rule (score of at least 10 + spell level), not a duplicate and within the known table. One swap per level replaces a
known spell with another of the same level. A mystic's connection spells come from `features[connection].connectionSpells`
(`{fixed: {level: slug}, variable?: slug}`), are added by `connectionSpells(char, data)` and do not count as known.
A variable-level spell holds the highest spell level the mystic can cast, and the fixed spells fill the lower levels.
The Crusader 6th-level spell has no link in Foundry; it is matched by name words ("greater resistant armor") and must match one spell of that level.

Known gaps: the mechanic gets the exocortex only. The drone is not offered, so drone mods and Control
Net's drone half are not modelled, and tricks that need a drone are left out of the trick pool. The solarian's solar weapon, flare and shield are
inventory items in Foundry, so the armor-or-weapon pick is left to gear. The Bully and Diplomat specialization powers
have no feature record to grant. The rule that an exocortex always keeps one mod from the 7th-level list
holds through the level gate, because swapping mods on level-up is not modelled.

Gear (`js/gear.js`): `char.gear = [{id, item, qty, equipped, slots?, fusions?}]`. `budget` uses the CRB wealth table; item level is capped at character level (AoN Gaining Wealth sets no hard cap, so this follows its APL guideline). `gearBlockers` also backs `allowed('item', slug, levelIndex, char, data, {into: gearId})`. `attackLines` filters weapon-scoped modifiers by `weapon.type`; Weapon Focus and the Weapon Specialization feat read the chosen type from `levels[i].choices[featSlug]`. Fusions carry no price in the data, so they cost 0.
